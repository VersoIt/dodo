# SYSTEM REQUIREMENTS SPECIFICATION

## 1. FUNCTIONAL REQUIREMENTS

### 1.1. User & Authentication
- The system must allow users to register and authenticate using email and password.
- The system must support Role-Based Access Control (RBAC) with roles: Client, Chef, Courier, and Manager.
- The system must allow users to view and update their personal profile (name, phone).

### 1.2. Product Catalog
- The system must allow users to browse and search for products (pizza, etc.).
- The system must allow Managers to create, update, and manage products in the catalog.

### 1.3. Order Management
- The system must allow Clients to create orders with multiple items and a delivery address.
- The system must support the application of promo codes for order discounts.
- The system must provide real-time order status tracking for the Client.
- The system must allow Managers to view analytics and manage all orders.

### 1.4. Kitchen Operations
- The system must automatically create kitchen tickets when an order is paid.
- The system must allow Chefs to view active tickets and update their preparation status.

### 1.5. Logistics & Delivery
- The system must allow Managers to assign couriers to ready orders.
- The system must allow Couriers to view assigned deliveries and update delivery statuses.
- The system must support real-time courier location updates.

### 1.6. Payments
- The system must process payments for orders through a dedicated treasury service.
- The system must handle payment status callbacks to trigger the order fulfillment workflow.

### 1.7. Communication & Notifications
- The system must provide a real-time chat between the Client and support/courier for active orders.
- The system must send automated notifications to users regarding order status changes.

---

## 2. NON-FUNCTIONAL REQUIREMENTS

### 2.1. Scalability & Architecture
- The system must be built using a Microservices Architecture to allow independent scaling of components.
- The system must use an API Gateway for request routing, authentication, and protocol translation (REST to gRPC).

### 2.2. Performance
- The API Gateway must handle requests with a latency of less than 100ms for non-intensive operations.
- The system must support concurrent WebSocket connections for the real-time chat service.

### 2.3. Security
- All sensitive data transmissions must be encrypted via TLS.
- User sessions must be managed using Secure JWT tokens with expiration.
- Database access must be restricted by credentials and network isolation.

### 2.4. Reliability & Availability
- The system must ensure data consistency using distributed transaction management where necessary.
- The system must utilize a message broker (NATS) for reliable asynchronous communication between services.
- Database changes must be managed through versioned migrations.

### 2.5. Observability
- All services must implement structured logging (slog) for production debugging.
- The system must provide health check endpoints for container orchestration (Docker/Kubernetes).

### 2.6. Maintainability
- The codebase must follow Clean Architecture principles (separation of domain, usecase, and infrastructure).
- All services must support configuration via environment variables and YAML files for different environments (dev/prod).
